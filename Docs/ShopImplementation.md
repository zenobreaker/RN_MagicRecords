# 로비 / 탐사 상점 구현

## 구조와 수정 범위

- 기존 `ShopUI.prefab`, `ShopSlot.prefab`, `ShopItemPopUp.prefab` 및 `UIManager`의 생성·스택 관리 흐름을 재사용한다. 별도 상점 씬이나 상점 매니저는 만들지 않았다.
- 저장소 HEAD의 `UIPopUpShop.SetData`는 `DrawPopUp`만 호출했다. `UIPopUp.OnEnable`에서 숨긴 CanvasGroup을 다시 표시하려면 `ShowPopUp`이 필요하다. 작업 시작 시 이미 있던 `ShowPopUp` 수정을 유지했고, 구형 프리팹의 CanvasGroup 누락, 비활성 풀 슬롯의 참조 초기화, 상세 팝업 중복 제출을 보완했다.
- `ShopItem.Copy`는 표시 데이터와 해석된 원본 상품 참조를 함께 복사한다. 로비의 기존 가격·통화·반복 구매 정책은 유지한다.

## 맵

- 기존 기본 5단계를 6단계로 늘린다. 기존 시작 노드와 일반 분기 단계를 보존하고, 마지막 보스 바로 앞에 상점 단일 노드를 추가한다.
- 직전 단계의 모든 노드는 상점 하나로 연결된다. 상점만 보스로 연결되고, 연결은 인접 단계 사이에만 존재한다. 단계별 노드 수는 최대 3개다.
- 생성 직후 연결을 검사한다. 상점 없는 구형 저장 맵은 기존 ID와 방문 정보를 보존하면서 보스 앞에 상점을 삽입한다. 맵의 선 렌더링도 노드 ID를 목록 인덱스로 가정하지 않도록 바꿨다.
- 상점을 닫으면 현재 노드를 완료 처리해 보스로 이동할 수 있다. 보스로 떠나기 전에는 현재 상점에 다시 들어갈 수 있다. 이미 보스에 진입한 구형 저장의 플레이어 위치를 강제로 되돌리지는 않는다.

## 재사용과 구매 흐름

- `NodeRouter`가 현재 씬의 기존 `ShopUI`를 연다. `UIShopSlot`에 아이콘·이름·가격만 표시한다. 설명과 구매 확정은 `UIPopUpShop`에서 처리한다.
- 재고는 `MapNodeInfo.shopStock`에 생성 시 한 번 저장한다. UI 재개방은 재추첨하지 않는다.
- 레코드는 기존 SO/RecordManager의 직업 필터와 미보유 조건을 사용한다. 정책에 명시된 등급·가격을 가진 유효 후보 중 중복 없는 최대 3개만 제시한다. 부족한 자리를 빈 상품으로 채우지 않는다.
- 탐사 상품은 클릭 시와 실제 확정 시 모두 탐사 재화를 검사한다. 부족하면 기존 토스트만 표시한다. 확정 중 재진입과 완료된 팝업 재제출을 막는다.
- 레코드와 15%/60% 회복은 각각 해당 노드에서 한 번만 구매할 수 있다. 이후 `판매 완료`로 표시하고 버튼을 비활성화한다. 판매 완료 문구에는 기존 슬롯의 한글 폰트를 사용한다.
- 스킬 교체는 기존 1012 이벤트의 `DRAFT_3` 후보 생성과 `UIRecordSkillUpPopUp` / `SkillEventSession`을 사용한다. 이벤트 데이터의 비용 50을 가져오되 `EventChoiceExecutor`의 선결제를 호출하지 않는다. 한 번의 교체를 확정하고 닫은 뒤 재구매할 수 있다. Esc/배경으로 취소하면 스킬 초안과 비용을 버린다.
- 상점 스킬 팝업은 슬롯과 스킬을 어느 순서로 선택해도 두 번째 선택 즉시 장착 초안을 반영한다. 빈 슬롯도 가능하며, 기존 교체 버튼 위치에는 `선택 슬롯 스킬 해제`를 표시한다. 실제 장착과 결제는 `적용 후 닫기`에서 확정한다.
- 이미 장착된 스킬을 다른 슬롯에 고르면 원래 슬롯을 비우고 대상 슬롯에 장착한다. 대상 슬롯의 기존 스킬은 해제되지만 목록에서 다시 선택할 수 있다. 이동·해제는 기존 스킬 배치 변경이므로 추가 구매나 추가 결제가 없으며, 새 후보 구매 1회 제한에 걸리지 않는다. 이번 팝업에서 구매한 스킬도 재결제 없이 이동·해제·재장착할 수 있다.
- 해제 버튼은 선택 슬롯에 스킬이 있을 때만 활성화한다. 슬롯을 비워도 스킬의 레벨·해금 상태는 유지한다. 장착 처리 후 이전 선택 조합을 소진하여, 해제할 슬롯을 선택할 때 이전에 선택했던 스킬이 자동 이동하지 않도록 한다. 취소하면 이동·해제 초안을 버리며, 확정 시 기존 장착 API로 변경 슬롯을 먼저 비운 후 최종 배치를 반영한다.
- 상점이 열린 채 씬/Play Mode가 종료될 때 이미 파괴된 탐사 매니저로 맵을 갱신하지 않도록 `StageUIController`에서 종료 상태를 확인한다.
- 상점 액티브 후보의 초안은 최소 Lv.1로 준비한다. 후보를 보기만 해서는 원본 스킬이 해금되거나 저장되지 않는다. 기존 레벨 업 버튼/확인 팝업/최대 레벨 제한을 재사용하며, 기존 비용인 기본 50 + (현재 레벨 - 1) × 25를 적용한다. 후보를 먼저 성장시킨 뒤 장착할 수도 있다. 교체와 성장 비용은 세션에서 합산하여 한 번만 차감하며, 취소·잔액 변경으로 인한 확정 실패 시 원본 상태를 유지한다.
- 체력은 기존 `HealthPointComponent`가 float를 사용하므로 반올림하지 않는다. `최대 HP × 0.15/0.60`을 더하고 최대치로 제한하며, 현재 HP가 0인 캐릭터는 회복하지 않는다. 같은 HP 이벤트/HUD 갱신을 사용한다.
- 맵 씬에는 전투 Player가 남지 않으므로, 탐사 중 Stage에서 등록된 캐릭터의 HP를 `ExploreRunSaveData.partyHealth`에 보존하고 다음 Player 인스턴스의 HP에 복원한다. 로비 원본 `CharStatusData`를 수정하지 않는다.

## 저장

- 상품 종류·레코드 ID·가격·판매 상태·구매 횟수는 기존 `stageNodeData.nodeInfos` 아래에 저장한다.
- 재화와 획득 레코드는 각각 기존 InventoryManager/RecordManager 저장을 사용한다. 확정 후 `AppManager.SaveIfDirty()`가 저장한다.
- 저장 포맷에는 선택 필드만 추가했다. 구형 저장에는 HP 이력이 없으므로 과거 손실 HP를 추정하지 않는다. 업그레이드 이후 실제 Stage에서 등록된 HP부터 유지된다.
- 기존 저장 방식은 여러 JSON 파일에 순서대로 쓴다. 프로세스 강제 종료/디스크 오류 시의 파일 간 원자성은 기존 한계로 남는다. 일반 UI 닫기·재진입·저장/불러오기와 중복 클릭은 별도로 검증한다.

## 미정 정책

`Assets/98.Datas/shopItemJsonData.json`에 기존 로비 데이터와 함께 다음 필드를 추가했다.

- `exploreRecordPrices`: 등급별 `{ rarity, price }` 목록. 현재 빈 목록이다. enum은 NORMAL=0, RARE=1, UNIQUE=2, LEGENDARY=3, MYTH=4다. 여기에 지정한 등급만 기존 유효 후보 필터를 거쳐 판매 대상이 된다.
- `exploreHeal15Price`, `exploreHeal60Price`: 현재 -1(미정). 이 상품은 가격 미정으로 표시하고 구매 팝업을 열지 않는다.
- 스킬 교체 가격은 기존 이벤트 1012의 50을 재사용한다.

레코드 판매 등급·가격과 회복 2종의 가격은 별도 확정이 필요하다. 테스트 가격은 테스트 코드 안에서만 주입하고 원래 정책을 복원한다. 실제 JSON에 임의의 판매 가격을 기록하지 않는다. 저장된 재고는 정책 변경에도 유지되므로 새 가격은 새로운 상점 재고 생성부터 반영된다.

## 검증 실행 방법

Unity에서 Lobby 씬을 연 뒤 `Tools > Shop` 메뉴를 순서대로 실행한다.

1. `1 Start Sandbox Play Mode (Lobby)`
2. 초기화 후 `2 Check Lobby and Map (Play Mode)`
3. `3 Load Exploration Test Scene (Play Mode)`
4. 맵 로드 후 `4 Check Exploration Shop (Play Mode)`
5. Play Mode를 종료한다.

테스트 저장 경로는 `Library/ShopRegressionSave-<고유 ID>`다. 검사 결과는 `Library/ShopRegression-checks.txt`에 기록된다. Dash는 별도로 `Tools > Skill > Run Dash Regression (Play Mode)`에서 실행한다.

실제 실행 결과는 `ShopRegressionResults.txt`를 참고한다. 상점 검증은 Unity Play Mode에서 실제 프리팹의 Button.onClick/OnSubmit/취소를 호출하며, 회복 대상은 테스트용 HealthPointComponent로 구성한다. 실제 플레이어가 전투 씬을 여러 번 오가는 장시간 수동 플레이 전체를 대체하지 않는다.
